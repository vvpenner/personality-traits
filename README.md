# personality-traits-bot

Telegram-бот практикума LESSSTRESS («Периферийный ключ») — 28-дневный курс
по снижению тревожности. Rust + teloxide + SQLite.

Вся логика сценария описана в **`perkeys.yaml`** (в корне репозитория),
медиафайлы лежат в **`questionnaire/abfi-1/data/`**.

## Логика работы

**Регистрация**
1. `/start` → бот просит поделиться номером телефона (кнопка Telegram).
2. После номера бот просит email — с напоминанием, что почта должна
   совпадать с почтой из заявки на практикум (с неё же проходятся опросы).
3. Далее — вступительное сообщение с кнопкой «Начать курс»
   (для уже начавших — «Начать курс заново»).

**Ежедневный цикл**
1. Участник получает информационное сообщение дня (`day_N_info`,
   картинка прикреплена к сообщению) с кнопкой «Начать практику».
2. По нажатию приходит практика (`day_N_practice`, аудио/документ
   прикреплены к сообщению) с кнопкой «Завершить практику».
3. По нажатию приходит выходное сообщение (`day_N_outro`), от которого
   отсчитывается пауза до следующего информационного сообщения.

**Еженедельный опрос** (после дней 7, 14, 21, 28)
1. Под выходным сообщением — кнопка «Пройти опрос».
2. По нажатию приходит сообщение со ссылкой на Google-форму
   (кнопка «Открыть опрос») и кнопкой «Опрос пройден».
3. По нажатию «Опрос пройден» приходит текст после опроса, от которого
   отсчитывается пауза до следующего дня.

**Пост-тест**: через месяц после завершения курса бот присылает
заключительный опрос (события `posttest` → `posttest_survey` →
`posttest_after`).

Все нажатия кнопок логируются в таблицу `button_events`
(telegram_id, message_id, button_id, action, время).

## Интервалы (тестовый режим)

Сейчас в `perkeys.yaml` пауза между днями — **1 минута**
(`delay_minutes: 1` у событий `day_*_info`), пост-тест приходит
через минуту после финального сообщения.

Для продакшена:
- `delay_minutes: 1440` (сутки) у всех `day_*_info`;
- `delay_minutes: 43200` (30 дней) у `posttest`.

`delay_minutes` у события — пауза ПЕРЕД его отправкой, отсчитывается
от нажатия предыдущей кнопки или отправки предыдущего сообщения.

## Медиафайлы (папка `questionnaire/abfi-1/data/`)

| Файл | Куда прикрепляется |
|---|---|
| `Титульная картинка.png` | вступительное сообщение |
| `День N.png` | инфо-сообщение дня N (N = 1..28, уже в репозитории) |
| `День N. Практика.mp3` | аудио практики дня N — **грузить по мере записи под этим именем** |
| `День N. Практика.pdf` | документ к практике (дни 1, 5, 7, 10, 11, 13, 19, 28) |
| `День N. Практика.png` | картинка к практике (дни 2, 10, 24, 25 — уже в репозитории) |
| `День 2. Отзывы к заданию 2.png` | выходное сообщение дня 2 (уже в репозитории) |

Отсутствующие файлы не ломают сценарий: бот пишет warning в лог
и отправляет сообщение без вложения.

Как прикрепляются вложения: если текст ≤ 1024 символов, он целиком идёт
подписью (caption) к первому вложению вместе с кнопками. Если длиннее —
первая часть уходит подписью, остаток — текстовым сообщением следом.

## Запуск

```sh
# 1. Токен бота от @BotFather:
cp .env.example .env
# отредактируйте TELOXIDE_TOKEN

# 2. Запуск:
cargo run --release
```

При первом запуске создаётся `bot.db` (SQLite) и применяются миграции
из `migrations/`. Бот работает через long-polling — внешний адрес
и вебхуки не нужны.

> ⚠️ Если у вас осталась `bot.db` от старой версии — удалите её:
> схема таблицы `users` изменилась (добавлен `phone`).

## Команды

- `/start` — регистрация или главное меню.
- `/restart` — завершить текущую сессию и начать курс заново.
- `/help` — список команд.

## Переменные окружения

| Переменная       | Значение по умолчанию                       |
|------------------|---------------------------------------------|
| `TELOXIDE_TOKEN` | токен бота от @BotFather                    |
| `DATABASE_URL`   | `sqlite://bot.db?mode=rwc`                  |
| `EVENTS_FILE`    | `perkeys.yaml`                              |
| `DATA_DIR`       | `questionnaire/abfi-1/data`                 |
| `RUST_LOG`       | `info,personality_traits_bot=debug,teloxide=info` |

## Структура хранения

- `users` — `telegram_id`, `phone`, `email`, `username`, `first_name`,
  `registered_at`.
- `course_sessions` — одна активная сессия на пользователя;
  `finished_at IS NULL` ⇒ курс идёт.
- `scheduled_messages` — очередь отложенной отправки (шедулер раз в 10 с
  забирает `send_after <= now`).
- `button_events` — журнал всех нажатий.
